Source code & audits

    How execution works

    1. Act as chooses the address used to simulate every call. Admin actions belong to the DAO Safe.
    2. Simulate runs the call read-only on the target network and decodes any revert. Nothing is signed.
    3. Send asks your wallet to sign. With Rabby, select the Safe account to create a Safe proposal for the signers.
    4. Add to batch queues it. The Batch tab exports a Safe Transaction Builder file so several actions execute atomically.

    Vaults

    Harvest all active vaults (one Multicall3 tx, permissionless)

    Calls harvest(callFeeRecipient) on every active vault with allowFailure so one bad vault cannot block the rest.

    Rescue stuck tokens (all vaults, one Safe batch)

    Scans every vault for ITP, the paired token and VELO left idle in the contract, and builds one inCaseTokensGetStuck(token) call per non-zero balance. Empty balances are skipped. LP (want) can never be withdrawn this way.

    Reward and penalty operations

    Operations require the staking contract owner. Reward deposits queue approval before deposit; the deposit may fail when simulated alone until approval executes. Safe batches preserve this call order.

    Burn ITP

    Optimism ·

    Calls burn(uint256), which destroys ITP from the sender's own balance and permanently reduces the total supply. This cannot be undone. Only the Optimism ITP has a burn function.

    DAO Safe treasury

    Scans every token, dHEDGE vault token, NFT and position (LP NFTs, veNFTs, streams) the Safe holds on the selected network, then moves the selected assets to another wallet in one Safe transaction.

    Assets 0

    Drain selected assets

    Every selected asset becomes one call in a single Safe batch (MultiSend). The batch is atomic: if any call fails, nothing moves, so simulate first. Failing assets are unselected automatically.

    Vault implementation (all vaults via beacon)

    Every vault is a BeaconProxy. factory.upgradeBeacon(newImpl) switches all of them in one transaction. Requires DEFAULT_ADMIN_ROLE.

    Factory implementation (UUPS)

    Replaces the factory logic itself through upgradeToAndCall(newImpl, 0x). Storage layout must stay compatible. Requires DEFAULT_ADMIN_ROLE.

    Deploy a new auto-compounder vault

    factory.createVault(...) deploys a BeaconProxy on the current implementation. Requires VAULT_CREATOR_ROLE. The new vault is owned by the factory; settings then go through the factory (needs SETTINGS_ADMIN_ROLE) or ownership can be moved to the DAO.

    Routes: JSON arrays of [from, to, stable, factory] hops. Output→native must start at the reward token (VELO) and end at ITP. A route may be empty when the reward token is itself a pair token.

    Batch

    The queue and its actions are scoped to the selected network. Export each network separately in Safe Transaction Builder; calls from different chains cannot execute atomically together.
